# Fundamentals cluster + Library clustering + calculator block — implementation plan

**Date:** 2026-07-07
**Status:** design validated (against the live code), ready to build.
**Owner decisions locked:** name = **Fundamentals**; the Library landing groups by cluster (each cluster = a field guide); calculators embed **natively** (not iframe) where relevant.

## 0. Goal

Add a **Fundamentals** cluster of public `/library` mini-lessons (Ohm's law, V/I/R, power, passives, reading a schematic/datasheet), grouped on a redesigned Library landing alongside the existing EEG/BCI cluster, each cluster downloadable as its own Field Guide PDF. Add a `calculator` content block so the `/tools` calculators can be embedded inline in a lesson (with a static PDF fallback). Cross-link Fundamentals into the courses via the existing glossary (`termRef`) + `ProjectMiniLesson` (SUPPORTING) spine.

Two surfaces of value: **product** (beginners get a place to learn the basics the L1 lessons assume) and **SEO/GEO** (top-of-funnel, AI-citable, cited + first-hand). Ranking honesty: this earns long-tail + AI-Overview citations + internal-link authority, not head-term wins ("ohm's law" is entrenched; `academy.*` authority is independent).

## 3. Data model + grouping

### Task 3.1 — migration (additive, PROD write → needs owner authorization)
Hand-authored SQL (`prisma migrate deploy`, per the prod-migrate workflow), new migration dir. **The backfill UPDATEs live IN this migration SQL file, right after the two ADD COLUMNs** (see below for why — NOT a separate seed script):
```sql
-- MiniLesson clustering: which Field Guide a lesson belongs to + its order within it.
ALTER TABLE "MiniLesson" ADD COLUMN "cluster" TEXT;
ALTER TABLE "MiniLesson" ADD COLUMN "clusterOrdinal" INTEGER NOT NULL DEFAULT 0;

-- Backfill: cluster the 12 existing EEG/BCI lessons + seed their within-cluster
-- order, one UPDATE per slug, clusterOrdinal 0..11 copied VERBATIM from
-- LIBRARY_NARRATIVE_ORDER (src/lib/library/narrative-order.ts:16-34).
UPDATE "MiniLesson" SET "cluster" = 'eeg-bci', "clusterOrdinal" = 0  WHERE "slug" = '<narrative-order[0]-slug>';
-- … one row per slug, in LIBRARY_NARRATIVE_ORDER sequence, through clusterOrdinal = 11.
```
`schema.prisma` `MiniLesson`: add `cluster String?` + `clusterOrdinal Int @default(0)`, then `prisma generate`. String (not enum) — same flexibility call as `onboardingGoal`.

**Backfill = UPDATE statements INSIDE the migration SQL (NOT a direct-Prisma seed script).** A seed script only touches whichever DB it is pointed at (prod), so the persistent test-pool clones and CI's freshly-migrated branch would get the ADD COLUMN defaults (`cluster = null`, `clusterOrdinal = 0`) but no cluster values — the eeg lessons would stay `cluster=null`/`clusterOrdinal=0` in every non-prod DB, contradicting the "`clusterOrdinal` is the single source of truth" claim and making the grouping unverifiable against the pool. `prisma migrate deploy` is idempotent + data-preserving and is run against prod (`pnpm db:migrate`), the test pool (`test:pool:refresh`, called by `db:migrate`), and CI's per-branch migrate uniformly — so an in-migration UPDATE reaches all three; a seed script reaches none but prod. Set the existing EEG/BCI lessons `cluster = "eeg-bci"` and `clusterOrdinal = 0..11` **copied verbatim from `LIBRARY_NARRATIVE_ORDER`** (`src/lib/library/narrative-order.ts:16-34`). This lifts the arc out of the hardcoded array and into the column: after backfill, `clusterOrdinal` is the SINGLE source of truth for within-cluster order and `LIBRARY_NARRATIVE_ORDER`/`byNarrativeOrder` are retired (§3.3). The landing renders only registry clusters (§4.1) + an "other" bucket, so a lesson with `cluster = null` disappears from a per-cluster section — since the backfill is in the same migration this can't happen at ship time, plus one of: (a) a follow-up `ALTER TABLE "MiniLesson" ALTER COLUMN "cluster" SET NOT NULL` (with a sensible default) once every row is clustered, so a future null-cluster seed can't silently vanish, **and/or** (b) §4.1 always renders the "other/unclustered" bucket as a safety net. Recommend both.

**Verify the backfill:** assert the eeg-bci `clusterOrdinal` sequence matches a **hard-coded frozen copy of the 12 slugs in arc order** (`what-is-a-bci`, `what-is-eeg`, `eeg-bci-guide`, `eeg-frequency-bands`, `motor-imagery-bci`, `eeg-electrodes-10-20-system`, `eeg-safety-and-isolation`, `biopotential-afe`, `ads1299-explained`, `eeg-noise-and-right-leg-drive`, `eeg-classification-csp-eegnet`, `control-a-drone-with-your-brain`) — do **NOT** import `LIBRARY_NARRATIVE_ORDER`: §3.3 deletes `narrative-order.ts`, so an import-based assertion won't compile. The frozen literal is the point — it pins the arc independently of the deleted module, so the EEG index + combined-book order can't regress when `byNarrativeOrder` is removed.

**Task 3.1a — make the EEG cluster values reproducible from source (else "single source of truth" is a lie outside prod).** The in-migration backfill is a one-shot in-place `UPDATE` of rows that already exist; it can NOT retro-touch rows inserted *later*. But the authoring source for the 12 EEG rows is the gitignored `scripts/_seed-eeg-cluster-phase1.ts` (+`phase2`/`phase3`), which predate the column and write `cluster`/`clusterOrdinal` for zero of them. So any DB rebuilt from those content scripts (rather than cloned from prod) — or a re-run of them against prod — reintroduces `cluster=null` EEG rows that §4.1 drops into the link-less "other" bucket. **Update the EEG seed scripts** (or fold the EEG rows into one canonical re-runnable seed) to write `cluster = "eeg-bci"` + the matching `clusterOrdinal` (0..11, same frozen arc) on every row they upsert, so the column value is reproducible from source and not carried solely by the one-time migration. Only then is `clusterOrdinal` genuinely the single source of truth.

### Task 3.3 — load helpers (`src/lib/library/load.ts`)

**Retire `byNarrativeOrder` from both helpers.** Today `listPublishedMiniLessons` (load.ts:71) and `loadPublicLibraryForBook` (load.ts:93) both `return byNarrativeOrder(rows)`, whose `LIBRARY_NARRATIVE_ORDER` ranks ONLY the 12 eeg-bci slugs — any fundamentals slug gets `+Infinity` and sorts to the END (the reverse of the registry, where fundamentals `order=0` precedes eeg-bci `order=1`). Leaving it in place = two competing ordering mechanisms. After §3.1's backfill the arc lives in `clusterOrdinal`, so:

- **Delete `src/lib/library/narrative-order.ts` + `src/lib/library/narrative-order.test.ts`.** Remove both `byNarrativeOrder` imports/calls from `load.ts`. The old arc is not re-imported anywhere — the §3.1 backfill-verify test pins it via a hard-coded frozen 12-slug literal (see §3.1), so no consumer needs `LIBRARY_NARRATIVE_ORDER` after deletion.
- **Two distinct orderings — do NOT collapse into one `clusterOrdinal` sort:**
  - **Per-cluster** load (`loadPublicLibraryForBook(cluster)`, and each bucket of `listPublishedByCluster()`) → `orderBy: { clusterOrdinal: "asc" }`. Safe as a DB sort because it is scoped to one cluster.
  - **Flat / combined** load (the no-arg `listPublishedMiniLessons()` that feeds the ItemList over ALL lessons, and the no-arg `loadPublicLibraryForBook()` that feeds the combined book) → a **JS sort keyed on registry `cluster.order` THEN `clusterOrdinal`** (add a small `byClusterThenOrdinal(rows)` helper reading `LIBRARY_CLUSTERS`). NOT a bare `orderBy clusterOrdinal` (interleaves fundamentals #n with eeg #n), and NOT `orderBy: [{ cluster }, { clusterOrdinal }]` (a DB sort on the `cluster` string is alphabetical — `"eeg-bci" < "fundamentals"` — putting EEG first, contradicting registry `order`). Cross-cluster order comes from the registry; within-cluster from `clusterOrdinal`.
    - **Null/unknown-cluster contract (mandatory — else it crashes the public ItemList):** `clusterByKey(key)` returns `LibraryCluster | undefined`, so a row with `cluster = null` or an unknown key has NO registry entry. `byClusterThenOrdinal` MUST key defensively: `clusterByKey(row.cluster)?.order ?? Number.POSITIVE_INFINITY` — a naive `clusterByKey(a.cluster).order` throws `TypeError` on undefined, and `undefined - n` yields `NaN` and corrupts the whole sort. This assigns null/unknown clusters a defined TRAILING rank, mirroring the safety-net the plan already mandates for the Map helper and the landing's "other" section. (`listPublishedMiniLessons` feeds this into `page.tsx:43`, which is exactly the null-cluster state §3.1/§4.1 insist will occur.)
- `listPublishedMiniLessons()` → also `select` `cluster` (+ `clusterOrdinal`) and, for the ItemList caller, return cluster-major (`byClusterThenOrdinal`).
- Add `listPublishedByCluster()` → `Map<clusterKey, lessons[]>` bucketed in registry order; rows with `cluster = null`/unknown fall to an `"other"` bucket that §4.1 MUST render.
- `loadPublicLibraryForBook(cluster?: string)` → optional `cluster` filter (per-cluster PDF, `clusterOrdinal asc`); no-arg (combined book) returns `byClusterThenOrdinal` so the two clusters group instead of interleave (see §4.4 for the combined book's dividers/labels). **The no-arg (combined) `select` MUST add `cluster` + `clusterOrdinal`** (today `load.ts:81-93` selects only slug/title/summary/byline/updatedAt/contentBlocks) so `byClusterThenOrdinal` has the fields to group on. The per-cluster arg path keeps its DB `orderBy: { clusterOrdinal: "asc" }` and needs neither field selected.

**Verify:** unit-test `byClusterThenOrdinal` + the grouping helper (pure over rows: fundamentals block precedes eeg block, within-block by `clusterOrdinal`; **a null/unknown-cluster row sorts to the trailing rank, no throw/NaN**). Confirm the eeg-only flat order still matches the old `byNarrativeOrder` output. tsc.
